# 客户档案生成功能设计

> 日期：2026-06-12
> 状态：已与用户确认设计，待编写实现计划
> 关联代码：`background.js` / `content.js` / `injected.js` / `popup.html` / `popup.js`

## 1. 背景与目标

现有 SaleSmartly 浏览器插件已经能被动监听并存储聊天消息、客户信息，并能针对"当前对话"生成 AI 回复建议。本功能在此基础上新增：**针对单个客户，拉取其完整历史对话，由 AI 抽取成一份固定字段的结构化需求档案**，用于：

- 一键填入 SaleSmartly 的客户备注栏（点一次同步一次，纯手动）
- 一键复制到剪贴板（兜底）
- 一键发送到后端

业务场景为跨境游销售客服（如印尼客人来华游九寨沟/成都等）。

## 2. 需求汇总

| 维度 | 决定 |
|------|------|
| 范围 | 单个客户（当前在 SaleSmartly 打开的对话） |
| 输出 | AI 按**固定字段模板**抽取需求档案；未提及字段填 `未提及` |
| 数据源 | **先拉完整分页历史**，再交给 AI；拉不到完整历史则降级用已抓到的消息 |
| 用途 | 弹窗展示（只读） + 填入备注栏 + 复制 + 发送后端 |
| 自动化 | **无自动同步**，全部手动点击（点一次同步一次） |
| 字段模板 | 存于 `profile-template.md`，可增减，不改代码 |

### 字段模板（初版）

```
国籍
出发地
机票是否需要代订 (是/否)
签证是否需要代订 (是/否)
是否首次来华 (是/否)
人数房型年龄
出行日期
游玩天数
旅行城市(行程)
导游(语言)
交通
```

字段以后随时增减，编辑 `profile-template.md` 即可。

## 3. 整体架构与数据流

延续现有四层注入式架构。点「生成档案」后的完整流程：

```
popup [生成档案]
   │  action: "get_customer_profile"  (chatUserId 取自 storage.userInfo)
   ▼
background.js
   │  1. 读取该客户的"请求模板"（之前录到的 get-message-list 请求）
   │  2. 经 content.js 指挥 injected.js 做分页重放
   ▼
content.js ↔ injected.js（页面上下文，自动带 cookie）
   │  循环重放 page=1,2,3... → 拼成完整消息数组 → 回传
   ▼
background.js
   │  3. 格式化完整对话 → 调 AI 抽取字段
   │  4. 解析为 label→value 结构化档案
   ▼
popup 展示字段 + [填入备注栏] [复制] [发送后端]
```

后续「填入备注栏 / 复制 / 发送后端」均为 popup 端对已生成档案的本地动作，其中「填入备注栏」需经 content/injected 操作 SaleSmartly 页面 DOM。

## 4. 详细设计

### 4.1 完整历史拉取（核心）

#### 4.1.1 录制"请求模板"（injected.js 新增）

现有 `injected.js` 只截获 `get-message-list` 的**响应**。增强为同时录制**请求**：

- 命中 `get-message-list`（fetch 与 XHR 两条路径都覆盖）时，打包：`url`、`method`、`requestBody`（含 `chat_user_id` 与分页参数名）、响应里的分页元信息（`total`、`list.length`、页大小线索）
- 经 content.js → background，按 `chat_user_id` 存入 `chrome.storage.local` 新键 `msgListTemplates`（每客户一条模板）

> 目的：下次知道这个客户的请求长什么样、分页参数叫什么、总量多少条，**不需要逆向 API**。

#### 4.1.2 分页重放（injected.js 新增）

点「生成档案」时，injected.js 用录到的模板循环请求：

- 复制模板 body，把分页参数（`page` / `page_num` / `offset`，名字从录到的 body 推断）从 1 递增
- 重放调用 `fetch(url, { method, headers, body, credentials: 'include' })`，跑在页面上下文，cookie 自动带
- **停止条件**（满足任一）：返回 list 为空 / 返回条数 < pageSize / 已达 total / 超过 50 页兜底
- 所有页拼接为完整消息数组回传

#### 4.1.3 前置条件与降级

- **未录到模板**（客户从未打开 / 未触发 get-message-list）：提示「请先在 SaleSmartly 打开该客户对话并加载一次消息」，并**降级**用 storage 里已抓到的消息先抽一份，档案标注「数据可能不完整」
- **重放失败**（鉴权过期、接口变更、网络错误）：报错提示，同样降级到已有消息

### 4.2 AI 抽取（background.js 新增）

新增 action `get_customer_profile(chatUserId)`，步骤：

1. 取该客户全部消息（完整拉取结果，或降级的已有消息）
2. 按时间排序，格式化为 `[客服]/[客户] 文本`
3. **长度兜底**：总文本超 ~60k 字符则截断，保留「最早 20 条（初始需求常在此）+ 最近大头」，档案标注「对话过长已截断」
4. 构造 prompt 调用现有 AI 链路（复用 `AI_CONFIGS` / `AI_PROVIDER`）
5. 解析返回为 label→value

#### Prompt 设计

- **不引入 `skills.md`**：抽取需求 ≠ 写回复话术，prompt 越聚焦越准、越省 token
- System：「你是跨境游客服需求分析助手。从客服与客户的对话中提取客户需求档案，只根据对话中明确出现或能合理推断的信息，**不要编造**。」
- User：完整对话上下文 + 字段列表（从 `profile-template.md` 读取）+ 规则：
  - 按字段逐行填写，未提及的填 `未提及`
  - 是/否类字段能从上下文判断就判断，判断不出填 `未提及`
  - 严格只输出字段行，不要多余解释

#### 输出格式（可解析 + 直接可贴）

AI 严格返回（label 后冒号，每行一个字段）：

```
国籍: 印尼
出发地: 未提及
机票是否需要代订: 是
签证是否需要代订: 否
是否首次来华: 是
人数房型年龄: 5人(3星级 2间房) 60-67岁
出行日期: 9.14-24
游玩天数: 10日
旅行城市(行程): 成都-康定木格措-四姑娘山+九寨沟
导游(语言): 需要英文导游
交通: 城际高铁,市内私家车
```

- **解析**：按行切，正则 `^(.+?):\s*(.+)$` → label/value map；不在字段表里的行丢弃（防 AI 夹带废话）
- 此原始文本即「复制」与「填入备注栏」的成品，零额外加工
- AI 输出 `max_tokens` 给 500（字段短）

### 4.3 UI（popup 新增「客户档案」Tab）

弹窗现有两个 Tab（当前对话 / 历史记录），新增第三个 **「客户档案」**：

```
┌─ 当前对话 ── 历史记录 ── 客户档案 ─┐
│  客户：印尼-张先生   [生成档案]      │
│  ─────────────────────────────────  │
│  国籍:            印尼               │
│  出发地:          未提及 (灰)        │
│  ...（只读字段列表）                 │
│  ─────────────────────────────────  │
│  [✏️ 填入备注栏] [📋 复制] [⇪ 发送后端]│
└─────────────────────────────────────┘
```

- 点「生成档案」：先显示「正在拉取完整历史…」→「AI 抽取中…」→ 渲染字段
- 字段值 `未提及` 用灰色显示
- 目标客户 = storage 中 `userInfo` 的 `chatUserId`；没有则提示「请先在 SaleSmartly 打开一个客户对话」
- 轻量缓存：生成结果存 storage（按 chatUserId），弹窗关再开能看到上次结果；**不自动重生成**

### 4.4 复制 / 填入备注栏 / 发送后端

#### 填入备注栏（content.js + injected.js 新增）

- popup → content/injected 在 SaleSmartly 页面定位备注输入框（textarea/input）
- 用原生 setter 技巧写值（应对 React/Vue 受控组件）：
  - `Object.getOwnPropertyDescriptor(HTMLTextAreaElement.prototype,'value').set.call(el, text)`
  - 派发 `input` / `change` 事件（bubbles）
  - 视需要触发 blur 或保存动作
- **定位选择器需在实现时对真实页面确认**（前置条件：把 SaleSmartly 打开到客户备注可编辑状态，读取该元素 DOM）
- **降级**：找不到目标元素 / 写入失败 → 自动改为复制到剪贴板 + 提示「未找到备注栏，已复制，请手动粘贴」

#### 复制

- 一键复制档案原始文本（含 `未提及` 字段，保持完整），复用现有 `copyText()`

#### 发送后端

- **默认方案**：复用现有 `POST /api/quick-create-customer`，payload：
  ```json
  { "name": "...", "channel": "...", "phone": "...",
    "remark": "国籍: 印尼\n出发地: 未提及\n...(整份档案文本)" }
  ```
- 后端零改动，与现有「抓取并发送」一致
- 若后端希望结构化入库，后续可加 `POST /api/customer-profile` 发 `{ chatUserId, profile: {...}, rawText, generatedAt }`

## 5. 错误处理与边界

| 场景 | 处理 |
|------|------|
| 未录到请求模板 | 提示 + 降级用已有消息抽，标注「数据可能不完整」 |
| 分页重放鉴权过期/失败 | 报错 + 降级到已有消息 |
| 对话为空 | 提示「无对话记录」 |
| AI 返回解析不出字段 | 显示原文 + 提示「解析失败，请重试」 |
| 备注栏元素找不到/写入失败 | 降级复制 + 提示 |
| 长对话超 60k 字符 | 截断（留最早 20 条 + 最近大头）+ 标注 |

## 6. 测试方式

浏览器插件无单测框架，靠手动 + 控制台验证（沿用 `[SS-Listener]` 日志前缀）：

- 在 SaleSmartly 打开一个有大量历史的老客户 → 验证能拉完整分页、条数对得上
- 验证档案字段抽取准确、`未提及` 正确
- 验证「填入备注栏」写入成功 + 降级路径
- 验证「发送后端」返回 200
- 验证字段模板增减后生效（编辑 `profile-template.md` 重试）
